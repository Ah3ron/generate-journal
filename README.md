# Генератор журналов посещаемости

> Создание `.docx` журналов посещаемости классов из простого текстового списка учеников. Один запуск — N готовых журналов, по числу секций `@ЖУРНАЛ` во входном файле.

## Описание

Скрипт `generate-journal` преобразует простой текстовый формат списков классов в готовые журналы посещаемости в формате Word. Журнал строится в альбомной ориентации A4: слева — колонка «№ п/п», затем ФИО ученика, затем колонки с датами учебных дней месяца и завершающий столбец «ИТОГ» с подведением отсутствующих по категориям (болен, по заявлению родителей, санаторий, неуважительная причина, всего отсутствующих).

Подписи дат в шапке таблицы развёрнуты вертикально (`btLr`), что позволяет ужимать колонку до 0.8 см и вмещать до 23 учебных дней на одной странице. Блок ИТОГ выделен жирной рамкой 2.25 pt, остальная таблица — тонкая рамка 1 pt. Каждый класс в журнале начинается с новой страницы, а в конце оставлено не менее 22 пустых строк под списки классов разной численности.

Все готовые `.docx`-файлы складываются в каталог `output/` (создаётся автоматически), что упрощает дальнейшую рассылку журналов учителям.

## Возможности

- Парсинг простого текстового формата (журналы → классы → ученики).
- Автоматический расчёт учебных дней месяца с учётом выходных (по умолчанию суббота и воскресенье).
- Поддержка дополнительных исключаемых дней через флаг `--exclude` (праздничные дни, каникулярные).
- Готовая вёрстка журнала: альбомная A4, фиксированные ширины колонок, вертикальные подписи дат.
- Жирная рамка для блока ИТОГ, тонкая для остального.
- Гибкое именование выходных файлов: `Журнал посещаемости <название>, <период>.docx`.
- Все файлы складываются в каталог `output/`, который создаётся при первом запуске.

## Требования

- **Python ≥ 3.14** — проект использует PEP 758 (безскобочный синтаксис `except A, B:`), который появился только в этой версии.
- **uv** — рекомендуемый способ управления зависимостями и запуска.
- **python-docx ≥ 1.2.0** — единственная runtime-зависимость для генерации `.docx`.

Версия Python определяется файлом `.python-version` и автоматически подхватывается `uv`.

## Установка

```bash
git clone <repo-url> generate-journal
cd generate-journal

# Синхронизировать зависимости (включая dev-группу с ruff и pyright)
uv sync --dev
```

`uv` сам скачает Python 3.14 при необходимости, создаст виртуальное окружение `.venv/` и установит все зависимости из `pyproject.toml`.

## Использование

### Базовый запуск

```bash
uv run generate-journal
```

Создаст журналы за октябрь 2026 года по списку из `ученики.txt` и положит готовые `.docx` в `output/`.

### Свои параметры

```bash
uv run generate-journal \
    --period "сентябрь 2026" \
    --students мои-классы.txt \
    --exclude "01.09,08.09" \
    --output-dir ./журналы
```

Здесь:

- `--period` задаёт месяц и год в формате `«название_месяца_родительном_падеже YYYY»` (например `сентябрь 2026`, `октябрь 2026`, `май 2027`);
- `--students` — путь к файлу со списками классов (см. формат ниже);
- `--exclude` — нерабочие дни (праздники, каникулы) в формате `ДД.ММ`, разделённые запятой;
- `--output-dir` — альтернативный каталог вывода (по умолчанию `output`).

### Пример вывода

```text
Учебные дни октябрь 2026 (22): 01.10 02.10 05.10 06.10 07.10 08.10 09.10 ...
Каталог вывода: /path/to/output
Журнал: 1 смена 1-2 кл и 3Б
   1 «А» — 25 чел.
   1 «Б» — 19 чел.
   ...
Создан: output/Журнал посещаемости 1 смена 1-2 кл и 3Б, октябрь 2026.docx
Журнал: 2 смена 6-7 кл
   6 «А» — 21 чел.
   ...
Создан: output/Журнал посещаемости 2 смена 6-7 кл, октябрь 2026.docx
Готово. Всего учащихся: 610
```

## Формат входного файла

Текстовый файл в кодировке UTF-8 (BOM допустим, считывается через `utf-8-sig`) со следующей структурой:

```text
# Строки, начинающиеся с #, игнорируются (комментарии).

@ЖУРНАЛ <название журнала>
# Название попадает в имя файла .docx и в шапку вывода консоли.

@КЛАСС <метка класса> | <ФИО руководителя>
# Метка — это «1 «А»» или «11 «Б»» — попадает в шапку таблицы.
# ФИО руководителя попадёт в подзаголовок «<метка> класс, <ФИО>».

# Дальше — имена учеников. По одному в строку ИЛИ через запятую.
# Пустые строки и строки с # между списком игнорируются.
Иванов Иван
Петров Пётр, Сидоров Сидор, Смирнов Семён
```

### Полный пример

```text
# ===== Списки учащихся для журналов посещаемости =====
# @ЖУРНАЛ ...  — название журнала (входит в имя файла Word)
# @КЛАСС 1 «А» | ФИО руководителя — начало нового класса
# Имена — по одному в строке ИЛИ через запятую. Строки с # игнорируются.

@ЖУРНАЛ 1 смена 1-2 кл и 3Б

@КЛАСС 1 «А» | Родевич Светлана Эдвардовна
Болтах Вера, Букштунович Илья, Юодо Ксения, Качалин Даниил, Литорская Александра

@КЛАСС 1 «Б» | Шароварова Елизавета Александровна
Аль Ксения, Ботян Егор, Бохан Эмилия, Брилевская Полина, Гринкевич Давид
```

### Правила разбора

1. Каждая строка обрабатывается отдельно; начальные/конечные пробелы и завершающая запятая удаляются.
2. Директива `@ЖУРНАЛ` начинает новый журнал; всё, что после неё на той же строке, становится названием журнала.
3. Директива `@КЛАСС` начинает новый класс внутри текущего журнала; строка разбивается по `|` — левая часть метка класса (напр. `1 «А»`), правая — ФИО руководителя.
4. Все прочие непустые строки считаются списком учеников текущего класса; они разбиваются по запятым, каждое имя обрезается от пробелов.
5. Если `@КЛАСС` встретился до `@ЖУРНАЛ`, журнал автоматически создаётся с названием `Без названия`.

## Параметры командной строки

| Параметр       | Короткий | По умолчанию    | Описание                                                |
| -------------- | -------- | --------------- | ------------------------------------------------------- |
| `--period`     | `-p`     | `октябрь 2026`  | Месяц и год, напр. `октябрь 2026`                       |
| `--students`   | `-s`     | `ученики.txt`   | Путь к файлу со списками классов                       |
| `--exclude`    | `-e`     | _пусто_         | Нерабочие дни через запятую в формате `ДД.ММ`         |
| `--output-dir` | `-o`     | `output`        | Каталог для сохранения `.docx`-журналов                |

Помощь по любой опции — `uv run generate-journal --help`.

## Выходные файлы

Каждый журнал сохраняется как `<output-dir>/Журнал посещаемости <название_журнала>, <период>.docx`.

```text
output/
├── Журнал посещаемости 1 смена 1-2 кл и 3Б, октябрь 2026.docx
├── Журнал посещаемости 1 смена 5 и 8-11 кл, октябрь 2026.docx
├── Журнал посещаемости 2 смена 3-4 кл, октябрь 2026.docx
└── Журнал посещаемости 2 смена 6-7 кл, октябрь 2026.docx
```

Каталог `output/` создаётся автоматически (`mkdir -p`-семантика) при первом запуске; если путь задан через `--output-dir`, он также будет создан по требованию, включая все промежуточные каталоги.

## Разработка

Линтинг и форматирование кода выполняются через `ruff`; статическая проверка типов — через `pyright`. Конфигурация живёт прямо в `pyproject.toml` в секциях `[tool.ruff]` и `[tool.pyright]`.

```bash
# Линтинг
uv run ruff check src/

# Форматирование
uv run ruff format src/

# Проверка типов
uv run pyright src/

# Запуск скрипта на тестовом наборе
uv run generate-journal --students ученики.txt --period "октябрь 2026"
```

Все три команды (`ruff check`, `ruff format --check`, `pyright`) должны возвращать `0 errors` после любых изменений — это базовый критерий готовности коммита.
